### Added
- Foundation: `CODE_OF_CONDUCT.md` (full Contributor Covenant v2.1 mirroring the org root; the org's "Reporting" section points to KooshaPari on GitHub).
- Foundation: `.github/ISSUE_TEMPLATE/config.yml` (disables blank issues, adds contact links for Security advisories, AgilePlus specs, and the Phenotype org so the private disclosure path is discoverable from the new-issue chooser).
- Foundation: `.github/dependabot.yml` (weekly updates for `github-actions` and `gomod`, 5-PR limit each; `npm` intentionally not enabled — see the YAML comment for the rationale and re-enable condition).
- CI: `.github/workflows/ci.yml` Go job now runs `gofmt -l .` and fails the build with a `::error::` annotation if any file is not gofmt-clean. Enforces the canonical Go formatter; previously a hand-written PR with bad indentation or unaligned struct fields would slip through.
- CI: `.github/workflows/ci.yml` Node test step is now gated on a real test framework being wired up. The package.json `test` script invokes `jest --config jest.config.mjs`, but the repo has no `jest.config.mjs` and no test files; the old step would fail on a fresh checkout with "ENOENT: no such file or directory, open 'jest.config.mjs'". The new step prints a clear `::notice::` and exits 0 when no jest config or no test files are present, so CI stays green and the missing infrastructure is visible in the Actions UI summary. A future PR that adds a config + tests will have the test step run automatically.
- Docs: `CONTRIBUTING.md` "Build & test" section now reflects the actual CI state — calls out the gofmt check, and adds a "Test framework status" subsection that documents the test-gating behavior with a concrete recipe for adding tests (config + TS transformer + at least one test file).
- Docs: `AGENTS.md` "Quality gates" line now lists `gofmt -l .` and `go vet ./...` (both enforced by CI) and defers `npm test` to `CONTRIBUTING.md`'s "Test framework status" subsection with a pointer, instead of asserting it's a gate when CI is currently gated on a real test framework being wired up.
- Docs: `CLAUDE.md` Stack table, Key Commands, and Key Files now match the post-correction reality — the Testing row points at `CONTRIBUTING.md` "Test framework status" (CI is gated on a real test framework being wired up), the Go commands include `gofmt -l .` (CI-enforced), and the dependabot entry no longer claims `npm` is enabled (it was dropped in 3fbdba7). Also fixed a dead reference to `.github/CONTRIBUTING.md` (the file doesn't exist).
- Docs: `.github/ISSUE_TEMPLATE/bug_report.md` "KWatch version" placeholder example updated from `0.1.0` to `1.0.0` to match the current `package.json` version. The actual reported version still comes from the binary's runtime version string (the Makefile injects it via `-X main.version=$(VERSION)` at build time).
- Security: `SECURITY.md` rewritten to direct vulnerability reports **off** the public issue tracker and onto the GitHub Security Advisories private path (matching the org convention and the `.github/ISSUE_TEMPLATE/config.yml` contact link added in the foundation commit). The previous text said "Please report security vulnerabilities by opening an issue with the security label", which is a real security bug — public disclosure leaks PoC details, affected versions, and call sites before a fix is available. The new policy includes a clear "do not open a public issue" warning, the GitHub Security Advisories URL as the preferred channel, direct maintainer contact via `CODEOWNERS` as a fallback, a "what to include" checklist, and a response timeline (48h ack / 5d triage / 14d patch).
- CI: `.github/workflows/ci.yml` Go and Node jobs now have `timeout-minutes: 10` (was: default 360). Bounds the blast radius of a hang — e.g. a `go test` deadlock, an `npm install` flake, a `tsc` infinite loop. Clean runs finish in well under a minute on a warm cache.
- CI: `.github/workflows/ci.yml` Go and Node jobs now `runs-on: ubuntu-24.04` (was: `ubuntu-latest`). `ubuntu-latest` is a moving target — it resolves to a different Ubuntu LTS every ~2 years. A green build today is not a guarantee of a green build next year if a future LTS brings a behavior change (apt mirror policy, Go runtime default, Node 22 patch). OmniRoute already pins `ubuntu-24.04`; this matches the org convention and gives reproducible CI.
- CI: `.github/workflows/ci.yml` `pull_request.branches` now matches `push.branches` (main, chore/**, feat/**, fix/**, refactor/**). Previously, a PR opened directly against a feature branch (e.g. a follow-up review commit to `chore/editorconfig-and-gitattributes`) would not trigger CI via the pull_request event — the gap was masked for the common "commit on feature branch, then PR to main" flow, but any PR targeting a feature branch directly would have skipped CI.
- Docs: `AGENTS.md` "Quick Links" no longer claims "Local CLAUDE.md: Not present". A `CLAUDE.md` is in fact at the repo root (foundation governance stack). The stale claim would have routed an agent away from `CLAUDE.md` and into `AGENTS.md` as a stand-in, which defeats the layered-governance design.
- Docs: `CLAUDE.md` "Useful entry points" and "Key Files" no longer reference `proc-service.ts` / `proc-cli.ts` — those files were deleted in commit `e7eff93` and the TS source layer is gone. `find . -name '*.ts' -not -path '*/node_modules/*'` returns no files. The CLAUDE.md also no longer says `kwatch/` (a directory) — `kwatch` is a compiled Linux ELF binary at the repo root, built from `main.go` via the Makefile. The doc fix leaves `package.json` scripts alone because rewriting them is a substantive project decision (either restore the TS layer or rewrite for the Go-only stack); the broken scripts are now flagged in "Useful entry points" so a new contributor doesn't waste time on them.
- Docs: `CLAUDE.md` "Useful entry points" now also flags the dead `dependencies` block in `package.json` — 4 packages (`@ffmpeg-installer/ffmpeg`, `blessed`, `chokidar`, `playwright`) that no source file in the repo imports. They were pulled in by the deleted TS layer; `npm install` now installs them and their transitive deps for no reason on every CI run. Same fix as the broken scripts (restore the TS layer, or strip the dead deps as part of the Go-only migration); left to the package owner because it's a substantive decision.
- Docs: `CLAUDE.md` "Useful entry points" now also flags the related, larger problem: `node_modules/` is tracked in git (7815 files per `git ls-files node_modules | wc -l`) despite `.gitignore` line 6 listing the pattern. The gitignore itself is correct — `git check-ignore -v node_modules/foo` returns the expected match, so new `npm install` output is properly ignored. The 7815 tracked files are historical: they were added in commit `d689e8e` ("tmp") before the gitignore was tightened in `e7eff93`, and the existing tracked files were never untracked. The fix is `git rm -r --cached node_modules/` (preserves the on-disk copy, untracks the index), which is a 7815-file diff and needs explicit owner authorization before running. Left as a documented next step rather than a unilateral commit.
